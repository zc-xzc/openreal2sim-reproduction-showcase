# 通用复现检查清单

[返回总览](../README.md)

本清单不执行安装，不保证适用于任意镜像，不替代上游文档。缺失的历史脚本不在此重建。

## 1. 固定来源

- 记录根仓库 commit、子模块 commit、工作树状态和补丁摘要。
- 从官方来源获取依赖，分别审阅代码、权重、数据和生成结果的用途许可。
- 记录基础镜像 digest、Python、PyTorch、CUDA、驱动与系统包版本。
- 不将私有数据、身份信息或凭据写入可公开运行记录。

## 2. 先检查环境，再运行模型

- 分别确认 GPU 可见、PyTorch CUDA 可用、编译扩展能导入。
- 对 OpenGL/EGL 等运行时检查真实动态库加载，不只看包名是否存在。
- 确认临时目录、磁盘与 inode 空间。inotify 限制也可能表现为类似空间不足的错误，不能直接清空目录处理。
- 不把特定环境的 `LD_PRELOAD` 或绝对库路径无条件复制到其他环境。
- 检查共享存储挂载及关键目录内容；子挂载可能遮住父目录内已有数据。不要把空目录直接当成数据丢失，也不要自动卸载挂载或复制覆盖。

## 3. 阶段执行与人工检查

- 先使用可合法获取的示例输入，小范围确认处理链路。
- 在固定版本中确认参数。对照版本的 preprocess 使用 `--key_name`，reconstruction 使用 `--key`，annotator 支持 `--key` 和 `--port`。
- `--stage` 表示从指定重建阶段继续后续阶段，不表示只运行该阶段。
- 必须确认 ground 与 object 掩码，实际保存后重开验证。不能把按钮点击或进程存活当作保存成功。
- 只读取可信来源的 pickle 场景文件；反序列化不可信 pickle 可执行代码。
- 默认不要把标注界面开放给互联网。核对实际绑定地址和共享开关后再启动。
- 对照版 annotator 的 `--share` 使用 Python `bool` 解析，传入字符串 `False` 不可靠；不能把该命令视为已关闭共享。运行前应在受控环境修正并验证配置。

## 4. 降级必须可见

- 每个阶段记录 `completed` / `skipped` / `failed` / `not_run`。
- 记录 skipped 的具体依赖或主动选择，并说明下游用了什么替代输入。
- FoundationPose 跳过时，不能把 ICP 姿态当作经过该阶段精修的姿态。
- 替代模块要记录身份与版本。mock 导入成功不能证明原库功能等价。
- 导出缺少 trajectory 时明确标记，禁止伪造轨迹或补零后当真值使用。

## 5. 冷启动与新样本分开验收

1. 保存系统层与依赖版本，独立保留数据层来源。
2. 从目标镜像新建环境。不要在检查前安装、恢复或自动修补。
3. 每项检查都必须影响失败计数与最终退出码；使用管道保存日志时保留真实验证进程的退出码。
4. 检查既有产物的格式与可读性，并另外说明它们是否由本轮生成。
5. 再在新样本上从头运行，记录人工步骤、失败与阶段状态。

“系统层通过”“数据层可见”“已有产物可读”“新输入处理通过”“仿真交互通过”应分别给结论。

## 6. 发布前复查

- 仅发布允许公开且有权分发的内容。
- 除去凭据、内网地址、SSH 端点、机器名、个人目录、截图、私有链接和不必要的数据来源信息。
- 默认不分发模型权重、容器镜像、原始图像、pickle 或场景大文件。
- 成功率、耗时、精度与加速比必须有对应实验，缺失即留空。
