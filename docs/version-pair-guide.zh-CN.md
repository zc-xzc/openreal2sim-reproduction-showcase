# 公开与私有版本的完整性边界

[返回首页](../README.md)

## 三层资料，各有明确范围

1. **公开技术版**：包含经筛选的技术文档、固定源码指针、安全补丁、配置、模板、CPU 工具和合成测试。覆盖现有可公开技术内容，不包含原始私人证据。
2. **私有工作版**：保留同一套当前技术文件，另加经过脱敏的来源索引、历史整理说明及保全材料定位信息。私有仓库不是自动获得上传原始截图、连接信息或凭据的许可。
3. **个人原件保全包**：保留本次四份上传 ZIP 的原始字节及其 167 个普通文件条目。两份会话归档合计 53 个条目、52 种不同内容；其余条目是先前生成的项目包和证据副本。167 不是 167 次实验，也不是去重后的证据数。

“相互完整”指每项资料有去向、共享技术内容一致、私人原件不误公开。它不要求把两份仓库变成字节相同的副本，更不表示模型、容器和 GPU 结果已经齐全。个人保全包不纳入任一 Git 仓库；仍按单独的私密附件保存。

## 如何核对两份技术版本

两仓库使用同一份 [同步契约](../reports/distribution-contract.json)，列出必须一致的共享文件。README 和 SHA256SUMS 按各自角色不同；私有附录不进入公开目录。

```bash
python3 scripts/check_repository.py
python3 scripts/verify_distribution.py
python3 scripts/verify_distribution.py --peer /path/to/other-checkout
```

前两条仅检查当前目录。第三条对本地另一份工作树做共享文件字节比较，不联网、不上传，不会打开个人原件。先分别运行两仓库的完整性检查，再做双向对比。没有传 --peer 时，不会声称两版本已经同步。GitHub 上的远端提交和 CI 仍需另查。

## 全部来源的去向

- 两份历史生成包：原件留在保全包；当前可用工具/文档由仓库继续维护。旧校验清单不覆盖新版，也不能替代新版测试。
- 49 文件归档：12 份只提炼技术摘要，2 份只提取匿名聚合统计，35 份不纳入公开证据。详见 [逐项审查](archive-evidence-review.zh-CN.md)。
- 4 文件摘要归档：原件留在保全包，仅用于理解资料结构和背景，不用作独立运行证明。其中一个模板与另一归档内容重复。
- 原始截图、照片、服务器/账号/个人路径、原始会话及未建立项目关联的检测 CSV/图表：只留个人保全材料。未因仓库是 private 而自动上传。

公开来源编号和行号表示内部审查所依据的位置；原件不公开，读者不能据此独立复现历史实验。公共代码来源、上游 MIT 全文和 CPU 合成测试则在公开版本中可检查。

## 仍未闭合的真实复现缺口

最终历史兼容补丁、完整递归源码与系统环境、模型的不可变版本及哈希、合法真实输入、标注保存闭环、完整 GPU 重建、视频/运动、仿真、真正新环境新输入冷启动仍需单独补证。检测训练指标不归入 OpenReal2Sim 重建成果，FoundationPose 跳过也不计作完整阶段通过。

本轮新增的是版本覆盖、来源去向与一致性检查，不是新的算法或 GPU 实验结果。许可范围见 [第三方声明](../THIRD_PARTY_NOTICES.md)；新增工具与文档仍未指定开放许可证。
